# Cosmos3 execution and scheduling source review

## Setup

Read-only review on 2026-10-09: vLLM-Omni `06afa310c942c0506f0ed9bdd189fa331c46bb97`, NVIDIA/cosmos-framework `7c5d20cf330db99f35327166ebe0408318f86a04`. No GPU benchmark or implementation change.

## Results

The inspected Generator path prepares fixed conditioning with UND, caches KV, then runs GEN denoising. Optional native prompt upsampling finishes before diffusion inputs are prepared; it is not YuE's continuous semantic AR workload.

| Layer | Observed behavior |
| --- | --- |
| Native framework | Packed inference with token or sample-count budgets; configurable Ray batching window |
| Generic Omni DiffusionEngine | RequestScheduler/StepScheduler selected by model capability |
| Inspected Cosmos Omni pipeline | One diffusion stage/process; single prompt, complete denoising loop; no four-method step-execution contract |

Native packing preserves order and admits an oversized sample alone, so its token budget is not a hard OOM guarantee. Native text-KV packing and cu_seqlens isolate samples/CFG branches; YuE's packed NAR already uses this principle. Omni single-device CFG runs branches sequentially; native packed CFG and multi-device CFG are separate implementations.

No ready-made GPU-time fair scheduler for continuous AR and NAR was found. A proposed scheduler would need costs rather than alternating counts: the recorded mixed 32 AR step was about 14.2 ms versus about 103 ms per complete NAR evaluation. Those are initial estimates, not isolated GPU service-time accounting.

## Scope

The review covers the pinned native and Omni paths. Their deployment stages and AR workloads differ from YuE. SeaCache, quantization and distilled steps change the algorithmic comparison; fair queuing remained a design hypothesis.
