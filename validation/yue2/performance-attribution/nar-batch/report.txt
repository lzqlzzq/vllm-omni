# NAR B1/B2 稳定性能对照

本轮完成四组交错配对（AB、BA、AB、BA），A=NAR1/VAE1、B=NAR2/VAE1。
**等长负载的吞吐收益四组均为正，但中位请求延迟也四组均变差；混合吞吐没有明确改善。**
因此支持保留可调 NAR 上限，默认 B1、B2 按负载选择，不支持全局替换为 B2。
本轮对照双方都是同进程独立声学队列，未重新比较上游 HOLD 单阶段。

### 配对稳定性

逐组先算 B2/B1 变化，再汇总；此处“配对中位”与上表“两个中位数之比”是不同统计量。

| 负载 | 四组吞吐变化 | 配对变化中位 | B2吞吐更高的组数 |
| --- | --- | ---: | ---: |
| 等长768帧 / 并发4 | +12.59% / +6.07% / +6.11% / +8.20% | +7.15% | 4/4 |
| 混合 / 并发4 | -0.97% / -0.17% / -0.27% / +2.22% | -0.22% | 1/4 |
| 混合 / 并发8 | -0.24% / -0.07% / -0.03% / +1.69% | -0.05% | 1/4 |
| 混合 / 连续16、上限8 | +0.12% / +0.06% / -0.07% / +1.36% | +0.09% | 3/4 |

等长收益范围 **+6.07%至+12.59%**；B2吞吐四次为6.922/6.537/6.520/6.532，
B1为6.148/6.163/6.145/6.037。前三次B1接近，第四次所有负载略慢，未删除该轮。
等长 E2EL/RTF P95 四组均降低 **5.86%–8.79%**，P50四组均增加 **0.72%–4.61%**。
连续负载RTF P95四组均增加 **2.33%–3.93%**，不是只由单个中位数造成的结果。

三种混合负载的配对吞吐变化均跨零；本轮不把不足1%的中位差异解释为可靠提速。
四组固定输入、单设备实验没有统计显著性或所有真实业务负载保证。
未固定GPU频率；活跃样本（利用率≥50%）频率中位第一轮B1为1860MHz，其余1845MHz，
温度中位第一轮B1为69°C、其余70°C，各轮最高72°C。没有明显臂间温度差异，
但监测不足以将细小波动归因于单一因素。
设备峰值B1为19278–19286MiB，B2为19314–19318MiB；不含之前4096帧长样本，
不能直接与前轮整套长短负载的显存峰值比较。

### 实际合批观察

独立[探针事件](evidence/observe-01/events.jsonl)记录：等长并发4为 **1+2+1**，
混合并发4为 **1+1+1+1**，14次VAE调用的batch维度均为1。
这与就绪队列不等待凑批、混合长度难以合批的解释相容；不是所有正式轮次的batch分布，
也不能仅据此确定之前6%/12%波动的全部原因。探针耗时不进入性能表。

## 方法

- A=NAR1/VAE1，B=NAR2/VAE1。两份 YAML 仅 NAR batch 上限不同。
- 四组相邻配对：AB、BA、AB、BA。每次独立启动并预热，避免沿用历史 B1 作正式对照。
- 每次预热混合长度并发4、等长768帧并发4、混合并发8，共16次输出。
- 正式负载为等长768帧并发4、混合并发4、混合并发8、连续16/上限8，共32次输出。
- 每组配对轮换正式负载的起始位置，同一组 A/B 顺序一致；共8个正式进程、384次输出（含预热）。
- 固定帧预算512/768/1024/1280，输入、seed、模型revision、4GiB AR KV与四个AR槽一致。
- 单RTX3090，驱动595.71.05；复用vLLM0.31.0、torch2.13.0+cu130环境，无MPS。
- 每轮计算Throughput、E2EL/RTF P50/P95，再报告四轮中位及相邻配对变化范围。
  Throughput=音频秒/整组墙钟；E2EL从实际提交至完整音频返回，RTF=E2EL/音频秒。
  连续负载客户端信号量等待不计入单请求E2EL，整组墙钟包含等待。
- 正式worker无probe/hook；另外运行等长与混合并发4探针，直接记录NAR batch成员和VAE形状。
  探针不能代表所有正式轮次的batch分布，探针时间不计入性能统计。
- 每个输出检查semantic数量、完整音频长度、有限值及错误标志；每个进程退出后检查GPU清空。
- 固定预算不是自然EOS；本轮不新增听感、HTTP、取消、shutdown或多卡验收。
