模型权重、worker、context 仍各一份，无嵌套 engine、无独立 DiffusionEngine、无公共 companion gate 改动。

默认部署保留原来的 24576 上下文、AR4、0.70 memory utilization、eager backbone。

去掉声学 HOLD 预算。旧客户端即使仍传多余 HOLD 预算也不需要据此占用声学期间的 AR 槽。

这不是与旧版所有内部部署参数完全兼容，特别是 `async_scheduling=True` 需要改为 false。

## CFG 容量与普通请求准入

不能把通用 CFG scheduler 的“两条最大上下文”启动限制套到所有部署，否则 AR1 及旧24k/小KV配置会无法启动。
YuE 专用 scheduler 复用原生初始化及公共成对调度方法，明确初始化所需 CFG 状态，但不修改公共代码：

- 没有 CFG 对时走 `OmniARScheduler.schedule`，CFG=1 保留普通 native AR 准入，不引入整段输出 KV 预约。
- 存在 CFG 对时复用 `OmniCFGARScheduler.schedule` 的原子接纳、完整 KV 预算预约及同步推进。
- 创建负分支前按两条实际前缀、输出预算及 block size 检查槽数、prefill token 上限和总 KV 容量。
- 无法容纳的对返回可解释的单请求错误，不会无限留在 waiting，也不会杀掉 engine。其后的普通请求仍可生成。
- `cfg_scale` 非有限/越界、ABC预算非法在 HTTP adapter 返回400；部署容量不足由 native 客户端抛出非致命请求 RuntimeError。

自动 ABC 阶段切换后才形成真实 negative prefix；因此自动请求的容量不足可能在 ABC 完成后报告。
HTTP truncation metadata 合并 ABC/semantic 两阶段，避免 semantic=false 覆盖 ABC=true。
