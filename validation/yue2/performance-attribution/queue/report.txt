# 新上游下的同进程声学队列 B=1 对照

收益仍然存在。新上游 + vLLM 0.31.0 下，并发 4 / 8 / 连续 16（上限 8）三轮中位
吞吐分别提高 **3.12% / 6.28% / 6.44%**，E2EL 与 RTF P95 均改善。
这支持继续保留可选 B=1 队列实验；尚不足以宣称所有负载受益或默认替换已完成验收。

固定上游为 [`5f95115e`](https://github.com/vllm-project/vllm-omni/commit/5f95115e703ffe51e03e40ae23c78ff841c3335e)
（2026-10-06，官方 main 与 fork origin/main 当时一致）。相对旧基线 `ee8fdab1`，
YuE 计算源码及默认 YAML 没有上游变化；共享运行时包含 vLLM 0.31 升级 `0b0d2d70`，
以及同步 runner 输出复制/无用 payload 减少 `1f47fa2f`。
本轮两组均在新版环境重新跑；没有以旧版结果直接充当新版对照，也没有逐提交消融归因。

## 范围与复现

独立源码：`experiments/yue2-upstream-queue-20261006/source/`。
远端：`root@connect.nmb2.seetacloud.com:27279`，实验根目录
`/root/autodl-tmp/yue2-upstream-queue-20261006-01`。
两组共用同一份新上游源码与 `631f5573` HF 加载修复；只按部署配置切换原单阶段
`yue2` 与可选 `yue2_queue`。旧主工作区及外层参考不改，不 commit/push。

- RTX 3090（UUID `GPU-b247abf1-1a25-c02d-a18c-55e4bef1f73a`），驱动 595.71.05；单 GPU，无 MPS。
- AR `max_num_seqs=4`，固定 4 GiB KV；同步调度、MR v1、TP=PP=1。
- 原编译和 CUDA Graph 保留；APC/分块 prefill 关闭。
- 声学 B=1；无额外 engine、线程、进程或 IPC，原 NAR/CPU 噪声/midpoint/VAE 不变。
- 四种固定长度 512/768/1024/1280 帧，原歌词/style/seed；完整音频检查，不是自然 EOS。
- 预热后测试并发 4、并发 8、连续 16/并发上限 8，各三轮。
- 先运行 baseline 三轮，再运行 queue 三轮，没有交错 AB。
- Throughput = 总音频秒 / 整组墙钟秒；E2EL = 单请求提交至完整最终输出；
  RTF = 该请求 E2EL / 音频秒。百分位先逐轮计算，再取三轮中位。
- 连续负载的客户端信号量等待不计入单请求 E2EL，整组墙钟包含全部 16 首。

## 输出与生命周期验证

- 24 项 CPU 回归、所有适用统一 pre-commit 检查通过。
- 两组各 93 次、共 186 次正式固定帧完整输出检查通过（包括预热/顺序样本）。
- 顺序 512/768/1024/1280 帧的完整 FP32 音频逐值相同；max-abs、RMSE、relative-L2 全部为 0。
  完整 `.pt` 留在远端，两组哈希与误差在 `summary.json`；本地保存 JSON/日志，不复制大型音频。
- 并发 84 对音频只有 **11 对**哈希相同：并发 4 为 6/12，并发 8 为 3/24，连续负载为 2/48。
  不宣称并发精确 parity、batch invariance 或听感/质量验收通过。
- 真实 GPU 验证零 AR 时声学继续完成、声学运行中与排队取消、取消后复用；
  8 请求/4 AR 槽下观察到第 5 个及第 6–8 个请求在旧请求仍执行声学时进入 AR。
- 真实 worker 最终模型 states、runner、声学 active/waiting 全空；smoke、lifecycle、
  baseline、queue 四次正常退出均清空 GPU 进程。
- 未新验自然 EOS、HTTP、进行中 shutdown、跨卡或 B>1。这是固定帧最小架构实验。
