# MPS on/off in the same-worker phase-queue version

## Setup

2026-10-09, H800 PCIe 80 GB/580.82.07; same frozen phase-queue source, AR32/KV32 GiB/client 64/NAR1/VAE1/window 0/fullCoT/CFG1/ABC 4096/semantic 9000. Off→on→on→off, independent processes, 64 matched prompts/seeds plus two full warmups each. MPS on used private servers and 100% active threads; no profiling hooks, clock or power changes.

## Results

| Run | Audio/s | E2EL P50/P95 (s) | RTF P50/P95 | Device peak (GiB) |
| --- | ---: | ---: | ---: | ---: |
| Off 1 | 20.909 | 405.532/639.043 | 1.889/2.688 | 59.132 |
| On 1 | 20.764 | 412.075/647.264 | 1.946/2.812 | 59.358 |
| On 2 | 20.694 | 409.770/645.305 | 1.908/2.714 | 59.214 |
| Off 2 | 21.011 | 407.732/641.849 | 1.916/2.782 | 59.395 |

Paired throughput changed −0.69%/−1.51%; E2EL P95 +1.29%/+0.54%; RTF P95 +4.59%/−2.46%. All 256 measured/eight warmup outputs passed. Each run retained one ABC and one semantic truncation. Temperature 49–65°C, median SM1230 MHz and zero sampled thermal throttling.

MPS did not improve this same-worker workload. This reduces the priority of cross-process context switching as its main bottleneck; it does not measure all scheduling or synchronization costs.

## Scope

Two pairs with different generation trajectories and unlocked clocks, comparing the same implementation with MPS on/off. CUDA 13.0 environment setup and failed startup/JIT attempts are recorded in the original report.
