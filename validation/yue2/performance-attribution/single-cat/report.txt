# Single-element concatenation removal and memory-pool diagnosis

## Setup

2026-10-10, H800 PCIe 80 GB/580.82.07, MPS off. Three single-element branches reuse one VAE tile, one latent chunk or one waveform; multi-element concatenation and the owned CPU output clone remain. Fixed-input tests compare the frozen FlashInfer/direct-KV implementation. Separate allocator profiling compares main `c548a110`+shared loading fix against the modified PR, 64 requests/two warmups each, AR32/KV24 GiB/client 64; PR NAR≤4/token 32768/window 200 ms/VAE1.

## Results

35 CPU checks passed. All 15 fixed-input FP32 audio pairs were exact, covering 2048 frames, 13000+1024 cross-chunk, short B4, mixed B3+B1 and long B4; cancellation/reuse passed. Eight short E2E requests plus one warmup executed two B4 jobs with no retry/OOM.

At the end of the PR profile, the default pool reserved 57.221 GiB and allocated 31.603 GiB: 25.000 GiB was wholly inactive segments and approximately 0.617 GiB inactive space inside live segments. Exit-time empty_cache released 25.000 GiB; the 2.496 GiB NAR pool released only after its graph anchor was dropped.

Both 64 request runs/two warmups completed, with zero retry/OOM and empty final states. The end-state reserved-memory gap 7.502 GiB comprised ordinary whole-segment cache 6.025 GiB, NAR pool 1.311 GiB, about 0.166 GiB ordinary internal inactive space and a small active difference. This is a synchronized end-state decomposition, not subtraction of unrelated peaks.

The three explicit single-element cats were removed. The memory investigation did not add allocator tuning or per-request cache clearing.

## Scope

Allocator snapshots paused the host for 70.917 s (PR) / 57.278 s (main), so timings include instrumentation. Individual cat-removal speedups were not measured. Tile views can still require internal contiguous copies, and exit-time cache release differs from memory available during requests.
